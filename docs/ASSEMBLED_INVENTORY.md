# 零件轉整機

## 使用方法

庫存 →「零件轉整機」→ 填整機名稱與唯一 DK 編號 → 加入實際庫存零件及數量 → 掃入實際零件序號；無序號需寫明原因 → 預覽成本及 BOSS／HALA → 核對後確認。

開啟、加入待核對清單與預覽都不寫入營運資料。確認後在單一資料庫交易內完成零件移出、整機入庫、成本／出資移轉與序號關聯。轉換不是銷售，也不新增採購付款或營業收入。歷史庫存不自動轉換。

每次建立一台、每台獨立庫存編號。若全部零件為 NEW，整機標 NEW；含中古或其他狀態零件時標 USED。不能把另一台整機或非資產品項加入。零件成本待確認、出資不足、序號不符、已被預留或庫存變更時阻擋並保留待確認畫面。

出售時，後台訂單只加入這台整機。前台網站訂購可沿用既有「轉成後台訂單／確認零件」並選此整機；不可再加入同一台內部零件。整機的售價仍由老闆決定，成本由組入零件帶入，不能用一般編輯直接改成本或任意補貨。

## 成本與出資

帳面成本採現有庫存成本快照；BOSS／HALA 本金依既有出資批次出庫順序分別移轉，不重新指定出資方，不以無來源缺口推定 HALA。未確認本金的來源先補齊再轉換。

一台混合出資整機在既有 funding lots 以兩個 0.5 的內部分配單位表示，各單位單價分別為該方本金的兩倍。總分配單位恰為 1，兩方本金以十進位 NUMERIC 精確保留；這些內部數量不是出資比例、也不是兩台電腦。單一出資方則為 1 單位。每台 SKU 僅允許整數一台出售，既有 BOSS 優先出庫可一次完整配置兩方本金；退回整機時原分配完整回復。庫存／訂單 UI 不把內部單位當成實際件數，詳細本金由管理員在轉換紀錄查看。

既有 `dk_sync_open_funding_lot_cost` 對一般庫存的行為保留；預組整機的分方本金不被總帳面單價覆蓋。轉換／拆回交易內的來源零件也保留原批次本金。新物料成本與出資明細放在僅管理員 RPC 可讀的 `inventory_assemblies`，不放進員工可讀的 inventory_items.extra；該處只留 assembly_id。

## 序號及售後

原零件序號保留品項、叫貨來源及 received_at，新增 assembly_id，狀態為 assembled，不能再單獨綁到其他訂單。整機另有一個獨立序號，可列印 DK 條碼貼紙。查詢整機或其中零件序號，都能看到原組裝紀錄及整機訂單狀態。

一般訂單流程也會同步預留／出售整機序號，不假造人工掃碼、檢測或出貨核對時間。若啟用原掃碼驗收流程，仍須實際核對整機、登記測試及掃描出貨編號。

未開單、未預留／出售且仍實際在庫的整機，可於轉換紀錄按「未售整機拆回零件」。必須確認已實際拆回，系統回復原零件、原序號及原出資；整機序號作廢，append-only 明細及紀錄保留。若原來源批次已改出資方或成本，阻擋拆回，需先核對。任何曾進訂單／出庫的整機，以及售後退貨機，不由此功能直接拆換。

退款沿用既有訂單流程，退回的是一台整機，內部零件不會再各入庫一次；驗收後重新上架／售後拆換的介面仍待後續開發。

## 安裝與驗證

遷移由 Supabase CLI 產生：`20261107001254_assembled_system_inventory.sql`。先安裝，再發布 UI。新增表、可選的 serials.assembly_id、serial status assembled，以及僅適用於預組整機的保護與同步；不回填歷史資料、不改寫既有正式單據。新表禁止直接客戶端存取，管理員 RPC 再次核對啟用的 admin；內部 helper／trigger 不開放直接執行。

隔離 SQL 使用目前正式純結構及虛構資料，遷移連跑兩次。涵蓋總值／兩方本金不變、失敗原子回滾（最後序號插入故障注入）、序號來源、版本變更、重試、手動增量／改成本／改出資／重複批次／小數銷售阻擋、拆回、一般及掃碼出售、退款、員工與匿名拒絕。

UI 檢查包括開啟／預覽不寫入、轉換確認、雙擊、模糊回應相同識別碼重試、未儲存提醒、權限改變清除本金資料，以及桌機／手機長序號版面。這些是隔離 SQL 與 mock UI／瀏覽器測試，不等同真實 Auth 或實機驗收。
