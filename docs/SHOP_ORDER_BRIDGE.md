# 網站訂購轉後台訂單

## 操作

1. 在「網站訂購」核對可供貨商品，確認運費及付款／取貨說明。
2. 按「轉成後台訂單／確認零件」。此時只開啟編輯畫面，不寫訂單、不扣庫存、不記帳。
3. 核對客戶與原商品清單，加入實際交貨的零件或整機。有現貨選「現有庫存」，缺貨選「需要採購」。新機以零件管理；整台收購的中古機可選已建檔的整機庫存。不要把整機與同一台的零件都當成出貨庫存加入。
4. 商品售價合計及運費必須等於原網站單。可使用既有的整單售價欄，避免整機售價及零件售價各算一次。狀態選「已確認」，勾選未曾手動建單及品項無重複後儲存。若舊訂單備註已有相同 WEB 單號，系統會阻擋新建，請先核對舊單。
5. 之後從「開啟後台訂單」處理收款、叫貨、到貨、組裝驗收、交貨及結單。既有需要採購的品項沿用叫貨單同步機制。若上次儲存回應中斷，重新開原單確認後儲存，檢查叫貨同步提示；不要手動另建相同訂單。

原網站已核實收款時，伺服器帶入原款項、日期及憑據，不再收第二次。尚未核實的轉帳回報只供核對，不視為收款。轉單後不再自動套用網站的48小時取消；需由後台取消／結案。

## 一筆交易只走一套帳

- `shop_order_links` 一張網站單只能連一張核心訂單，核心訂單也只能連一張網站單。連結與訂單建立同一交易完成；重試只回傳原單，不覆寫。
- 後台訂單扣實際零件／整機、計算既有成本與出資。官網 `inventory.qty` 是上架可售數量；完成核心訂單時同步減少一次，沒有第二筆核心庫存或成本分錄。
- 核心確認收足款時，客人查單顯示已核實；完成且交付時顯示已交付。後台取消／洽談失敗／退款同步結案。
- 已轉單的舊網站收款、取消與交付 API 不能繞過後台。官網數量不足時整筆結單回滾，核心庫存及帳務都不提交。
- 已售商品退款後，沿用原後台退貨入庫；官網數量不自動加回。檢查機況、確認可售後再上架。
- 已連結訂單應收總額須符合原網站單，避免客人看到的應付金額與後台不同。需要改價的情境尚未提供重新報價流程。

## 安裝與驗證

遷移：`supabase/migrations/20261106233806_shop_core_order_bridge.sql`（由 CLI 產生檔名）。先安裝資料庫，再發布前端。只新增連結表與函式／觸發器，不回填歷史網站訂單，也不改寫歷史營運資料。連結不允許刪除核心／來源訂單，需使用取消或退款保留紀錄。

權限：連結只允許啟用管理員讀取；轉單 RPC 僅 authenticated 可呼叫，內部再次核對管理員。內部觸發函式不開放直接呼叫。無前端私鑰。

隔離測試使用正式純結構 fixture 和虛構資料，涵蓋重複轉單、版本衝突、假收款、售價不符、服務冒充商品、正常收款／結單、庫存成本、退款、不重複扣庫存、官網數量不足原子回滾、舊流程相容與權限。UI 測試涵蓋轉單前不寫入、空白品項待確認、已轉單開原單、讀取連結失敗阻擋及未儲存保護。

## 尚未包含

- 預組新機的「零件轉成品」與拆機成本轉換介面。不能把新增整機當成已具備轉換功能。
- 固定配置／商品對照表的自動帶入；目前由人核對實際品項。
- 歷史網站單自動配對（避免重複記帳）；已交付、已取消或測試單不轉單。
- 真實 Auth 的獨立環境全畫面驗收、手機／掃碼機／紙本實機驗收。
