# DK 掃碼作業

## 員工操作

- 到貨：叫貨單 → 品項「登記到貨」→ 掃每件 S/N（每次掃碼換行）→ 確認到貨。沒有原廠序號可按「產生一個 DK 序號」並列印貼紙。生成或列印不會入庫。
- 組裝：儲存訂單後重新開啟 →「掃碼組裝／出貨核對」→ 選零件 → 掃 S/N →「確認裝入這件零件」。只能使用同品項、未售出且未綁其他訂單的序號。每件只能綁一次，不能超量。
- 無序號：選品項，填至少五個字說明，按「確認此品項無序號」。已有可用序號的品項不可豁免；更換品項或數量會使舊豁免無效。
- 拆換：掃原 S/N 按「移除此序號綁定」。採購專用件維持原單保留，只移除組裝確認；一般未指定用途序號會解除綁定。重新組裝後須重做測試與出貨核對。
- 出貨：記錄檢測結果 →「確認整機測試通過」→ 列印訂單條碼 → 掃訂單編號 →「核對出貨訂單」。最後照既有流程儲存收款、交付、結單，才由原庫存流水扣庫存。
- 售後：訂單編輯畫面「售後查詢」掃 S/N 或訂單編號，可找回原型號、訂單、到貨與檢測紀錄。查詢不改資料。

商品共用條碼只能識別型號；組裝追蹤必須掃每件 S/N。此版組裝依庫存品項 ID 核對，不會用相似名稱猜型號。列印採本機 Code128，既可手動輸入，也可使用 USB／藍牙鍵盤模式掃碼槍。

## 資料與部署

新增 `inventory_serials.assembled_at`、`order_scan_checks` 及兩個授權 RPC。無歷史資料回填或刪除，舊訂單不會自動加入掃碼強制驗收。第一次確認組裝或登記無序號才加入。

到貨有填 S/N 時呼叫 `backoffice_receive_scanned_purchase`，在同一交易完成原採購入庫及序號登記；任一步失敗均回復。無 S/N 的舊呼叫維持原流程。不得先上傳新版前端而尚未安裝遷移，沒有新 RPC 時會失敗，不降級到分段入庫。

已加入掃碼流程的訂單，在後端延後觸發器核對最終訂單明細、測試、出貨條碼及全額收款；未通過就回復整筆結單。沒有新增第二條扣庫存路徑。取消釋放保留序號；退款標記 returned，避免直接再次售出。

部署順序：PR／CI 通過並確認合併 → 套用遷移 → 核對欄位、函式及權限 → 發布前端 → 唯讀 Smoke Test。正式營運資料不可用於測試。

## 驗證與限制

隔離測試使用正式資料庫的純結構 fixture，不含營運資料。涵蓋：交易失敗回復、重複序號、型號錯誤、重複組裝、拆換失效、出貨編號不符、後端結單阻擋、成本與流水不重複、匿名權限拒絕、遷移重跑。

瀏覽器測試涵蓋桌機／手機無溢出、Enter 不寫入、DK 序號及本機條碼列印。這不等同實體掃碼槍、標籤印表機或真實登入完整 E2E 驗收；正式交給員工前仍須用實機完成一張隔離測試訂單。

廠商平台既有商品條碼建檔／查詢獨立運作。本版不會跨系統同步、複製廠商資料或改其庫存；DK 售後紀錄留在 DK 後台。
